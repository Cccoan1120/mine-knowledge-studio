# Mine 个人项目展示 HTML 演示稿设计说明

## 1. 目标

为 Mine 个人知识库项目制作一份中文、16:9、可交互的单文件 HTML 演示稿，用于个人作品集、产品岗位面试和项目展示。

演示稿需要让第一次接触 Mine 的观众在 8 至 12 分钟内理解四件事：

1. Mine 解决的真实问题是什么。
2. 产品方案如何从调研、痛点和竞品观察中形成。
3. Mine 已经实现了哪些可验证的功能闭环。
4. 项目如何通过 Vibe Coding 持续迭代并完成线上部署。

## 2. 受众与叙事立场

主要受众是产品经理、AI 产品、内容产品或复合型岗位的面试官，也兼顾个人作品集浏览者。

叙事采用“产品作品集”为主、“个人构建故事”为辅的组合：

- 主线：问题发现 → 用户调研 → 痛点定义 → 竞品分析 → 产品机会 → 原型与闭环 → 迭代 → 结果与复盘。
- 辅线：通过 Code Assistant 和 Vibe Coding 把想法持续实现为可访问产品。
- 不把“零基础”作为核心卖点；重点体现产品判断、闭环设计、AI 工作流和落地能力。
- 用户调研定位为探索性研究，不虚构样本数、转化率、增长率或用户评价。

## 3. 交付物范围

最终只新增一个自包含 HTML 演示文件，暂定路径为：

`Mine 个人知识库项目展示.html`

演示文件应具备：

- 1920 × 1080 的固定 16:9 舞台，按浏览器窗口等比缩放。
- 方向键、PageUp/PageDown、空格键和底部按钮翻页。
- 当前页码和总页数。
- 使用 `localStorage` 保存当前页，刷新后恢复。
- 支持直接在浏览器打开，不依赖构建工具。
- 支持浏览器打印或导出 PDF。
- 支持 `prefers-reduced-motion`，减少动效模式下不执行非必要过渡。
- 在线体验和 GitHub 链接均可点击，并在新标签页打开。

不在本次范围内：

- 可编辑的 `.pptx` 文件。
- 演讲者备注系统。
- 后端服务或 Mine 产品代码修改。
- 虚构用户数据、竞品数据或业务效果。

## 5. 内容结构

演示稿共 13 页，每页只承担一个主要信息任务。

### 01 封面

- 标题：Mine
- 核心表达：把外部信息变成你的专属知识库
- 辅助信息：AI 个人知识库 / 个人项目展示 / Vibe Coding
- 使用产品主界面作为核心视觉，不堆叠功能列表。

### 02 项目概览

- 一句话定位：面向内容创作者和知识工作者的 AI 素材收纳与内容输出工作台。
- 目标用户：需要持续收集、整理和复用信息的内容创作者与知识工作者。
- 产品闭环：收集 → 整理 → 关联 → 问答 → 输出。

### 03 项目起点

- 典型现象：收藏了大量文章、视频、播客和截图，真正创作时仍然从零开始。
- 强调问题不是“信息不够”，而是信息没有被整理成可检索、可引用、可复用的素材。
- 使用“散落来源”到“统一工作台”的前后关系表达，不使用虚构统计数字。

### 04 探索性用户调研

- 调研渠道：小红书、抖音、B 站内容与评论观察，以及围绕个人知识管理和内容创作的反馈收集。
- 关注问题：用户保存什么、为什么找不到、何时需要引用、如何把素材变成内容。
- 明确标注：本页为探索性问题验证与反馈归纳，不代表统计研究结论。

### 05 痛点定义

归纳四个核心痛点：

1. 素材分散在不同平台和文件中。
2. 保存后缺少结构，检索和回忆成本高。
3. AI 回答缺少清晰来源，难以核对。
4. 从素材到文章、笔记或脚本仍需重复整理。

### 06 竞品分析

使用二维或表格式比较，不做品牌 Logo 墙。比较对象按真实产品类别组织，必要时列出代表性产品：

- 快速记录与笔记类。
- 知识库与协作文档类。
- 阅读收藏与稍后读类。
- AI 问答与研究助手类。

比较维度固定为：多来源收集、结构化整理、来源可信度、内容输出。竞品能力只引用可核实的公开资料，不使用主观分数伪装精确结论。

### 07 产品机会与方案

- 产品机会：从“保存内容”升级为“复用素材”。
- 核心方案：把外部材料统一转为可编辑素材，通过 AI 提炼、关联和问答，最终生成可继续编辑的内容草稿。
- 给出产品原则：本地优先、来源可追溯、人在回路中、输出可继续修改。

### 08 产品原型与信息架构

以 Mine 三栏主界面为核心：

- 左侧：素材库、分类和标签。
- 中间：素材列表与 Markdown 编辑。
- 右侧：Mine Copilot 的收纳、问答和输出。

使用真实界面截图和标注线解释信息架构，不重新绘制一套与产品不一致的假界面。

### 09 核心产品闭环

展示五步闭环：

1. 导入公开链接、图片、音频、视频或 Markdown。
2. AI 生成标题、摘要、标签和主题。
3. 关联相似素材，形成素材网络。
4. 基于素材库问答并展示来源。
5. 生成大纲、选题卡、研究摘要、公众号草稿、小红书笔记或短视频脚本。

### 10 关键能力

选择四项最能支撑产品定位的能力：

- 多来源素材导入。
- AI 收纳与标签整理。
- 带来源的素材库问答。
- 多格式内容输出。

页面不做通用功能卡片墙，而使用一张主界面图配四个编号注释，或使用不等宽版式体现主次关系。

### 11 迭代路径

以本地提交记录和代码事实整理阶段，不编造具体用户增长结果：

- Demo 闭环与基础素材库。
- Markdown 编辑与本地素材库。
- 登录注册和用户数据隔离。
- 稳定导入、来源追踪与可信引用。
- 媒体导入运行时与线上部署。
- 认证和工作区体验持续优化。

每个阶段说明“发现的问题”和“对应调整”，避免只列功能名称。

### 12 技术实现与 Vibe Coding

- 前端：React + TypeScript + Vite。
- 后端：Express。
- 数据：Prisma + Postgres / Neon。
- AI：OpenAI-compatible API、视觉和转写能力按环境配置。
- 部署：Render 单服务承载 API 与前端静态文件。

Vibe Coding 叙事聚焦：把需求拆成可验证的小闭环、通过 Code Assistant 快速原型、结合真实报错和测试持续修正，而不是“一句话生成整个产品”。

### 13 复盘、边界与下一步

- 已完成：从素材收集到可信问答和内容输出的完整可演示闭环。
- 当前边界：付费、私密、登录保护或平台限制内容不会被绕过；部分图片识别、音视频转写依赖外部模型和运行环境。
- 下一步：优化媒体识别稳定性、增强素材关联质量、探索移动端体验。
- 主按钮：在线体验 Mine。
- 次按钮：查看 GitHub。

## 6. 视觉系统

视觉语言从 Mine 当前界面提取，不另造无关品牌风格。

### 色彩

- 背景：暖灰白 `#F3F5F2`。
- 纸张表面：`#FFFFFF` 与 `#F8F9F7`。
- 主文字：墨绿黑 `#1D2420`。
- 主强调：深绿 `#2F5B4D`。
- 次级信息：灰绿 `#68716B`。
- 线框：`#D9DFDA`。

整套演示只使用一个主强调色。蓝色仅在真实产品旧截图中自然出现，不作为新演示的第二套主题色。

### 字体与排版

- 中文优先使用与 Mine 一致的 `PingFang SC`、`Microsoft YaHei`、`Noto Sans CJK SC` 字体序列。
- 标题主要依靠字级、字重、行距和留白形成层级，不用大量卡片或图标装饰。
- 1920 × 1080 画布中的正文原则上不小于 24px，辅助标签不小于 20px。

### 版式

- 视觉隐喻为“数字素材研究手册”：暖白纸面、细线网格、克制标注、真实界面截图。
- 每页有固定页码和章节标识，但不重复放置大面积导航。
- 主要节奏由大标题、截图裁切、编号和细线关系构成。
- 避免大面积紫蓝渐变、玻璃拟态、通用 SaaS 图标卡片、虚构数据和装饰性 3D 图形。

### 动效

- 翻页采用短促的横向位移和透明度过渡，用于表示章节推进。
- 单页内只对关键标注做有限的分步出现。
- 动画不循环，不延迟阅读；减少动效偏好下完全关闭非必要动画。

## 7. 素材策略

- 优先使用仓库中的真实 Mine 界面截图。
- 实现阶段先运行或访问当前版本，若能稳定获取最新截图，则替换较早截图。
- 若无法获取新截图，使用现有图片并在演示中避免声称其代表精确的当前 UI 状态。
- 图片嵌入 HTML，保证文件移动后仍可正常显示。
- 不使用未经授权的竞品截图；竞品页以文字维度和简洁结构为主。

## 8. 实现结构

最终 HTML 保持单文件，但内部按职责组织：

- HTML：13 个带 `data-screen-label="01 Title"` 格式标签的 `<section>`。
- CSS：设计 tokens、舞台缩放、幻灯片布局、打印规则和减少动效规则。
- JavaScript：翻页状态、缩放计算、键盘与按钮事件、页码、`localStorage`。
- 链接：使用标准 `<a>`，保留键盘焦点样式，并增加 `rel="noreferrer"`。

不引入 React、幻灯片库或远程运行时。实现保持纯 HTML、CSS 和 JavaScript，以减少依赖和离线失败点。

## 9. 异常与降级

- JavaScript 关闭时，所有页面按文档流纵向显示，链接仍可点击。
- 图片加载失败时显示明确的替代文字区域，不留空白黑框。
- localStorage 不可用时仍可正常翻页，只是不保存位置。
- 窗口尺寸极小时维持完整画布等比缩小，不把单页内容重新排成网页长页。
- 打印模式关闭控制按钮和动画，每张幻灯片独占一页。

## 10. 验收标准

内容验收：

- 13 页结构完整。
- 用户调研明确为探索性研究，不包含虚构样本量。
- 竞品分析有统一维度，并基于可核实公开信息。
- 产品能力与仓库当前代码、README 和界面相符。
- 线上体验与 GitHub 两个链接均可点击。

交互验收：

- 方向键、PageUp/PageDown、空格和按钮可以稳定翻页。
- 首尾页不会越界。
- 页码正确，刷新后恢复上次页面。
- 浏览器缩放或改变窗口尺寸后画布仍保持 16:9。

视觉验收：

- 主要视口无文字溢出、遮挡或图片拉伸。
- 正文和操作控件对比度清晰。
- 不出现大面积渐变、虚构数据、无意义图标或重复卡片墙。
- 真实截图在投屏比例下仍能辨认核心区域。

技术验收：

- 文件可直接双击打开。
- HTML 标签和脚本无明显语法错误。
- 浏览器控制台无阻断性错误。
- 在线体验和 GitHub 地址返回有效响应。
- 打印预览中每页独立成页。

## 11. 实施前资料核验

实现阶段需要完成以下只读核验：

1. 从官方页面核对代表性竞品的当前公开能力。
2. 从 README、核心组件和近期提交再次确认 Mine 功能与迭代顺序。
3. 检查在线体验和 GitHub 地址是否仍可访问。
4. 尝试获取最新线上界面截图；失败时使用仓库现有截图并如实说明。
