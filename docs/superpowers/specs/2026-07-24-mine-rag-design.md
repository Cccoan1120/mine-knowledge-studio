# Mine 混合 RAG 第一阶段设计

## 目标

将现有基于关键词筛选、整篇素材上下文的问答升级为混合 RAG：Markdown 结构化分块、服务端 Embedding、Postgres 关键词与向量联合召回、可信引用和当前会话内的轻量多轮追问。

本阶段不实现 LLM Wiki 页面、实体抽取或知识图谱。检索层保持独立，供后续 Wiki 复用。

## 产品约束

- 单用户知识库按 1 万条素材以内设计。
- 默认检索整个知识库，可按当前素材、主题、标签或手选素材筛选。
- 中文优先并兼容英文。
- 多轮消息仅保留在当前浏览器会话，不持久化聊天记录。
- 无 Postgres 时保留现有关键词问答，并明确标记为基础检索。
- 回答优先使用个人知识库证据。仅在证据不足时显示独立的模型补充区域。

## 索引与数据

Neon 启用 `pgvector`，新增知识分块和索引任务数据。分块记录用户、笔记、标题路径、原文偏移、内容哈希、关键词、1536 维向量和索引版本。

Markdown 使用结构化语法树按标题、段落和列表切分，目标约 700 tokens、最大 1000 tokens、重叠约 100 tokens。中文生成双字词，英文生成规范化词项。关键词使用 `tsvector` GIN 索引，向量使用 cosine HNSW 索引。

新建或编辑笔记时创建持久化索引任务，删除笔记时级联清理任务和分块。后台任务在现有 Express 服务内运行，通过 `FOR UPDATE SKIP LOCKED` 取任务，失败按 5 秒、30 秒、5 分钟退避，最多自动尝试 3 次。内容哈希防止旧任务覆盖新内容，服务重启后继续处理。用户登录后幂等补齐缺失或过期索引。

## 检索与回答

轻量多轮最多提交最近 6 条消息。模型先把追问改写为独立检索问题；改写失败时使用当前问题和最近用户问题组成降级查询。

向量与关键词各召回前 30 个分块，使用 Reciprocal Rank Fusion 本地融合，去重后限制每篇素材最多 2 个分块。最终最多向回答模型提供 8 个分块、5 篇素材，不增加模型重排调用。

知识库回答的每条引用必须包含分块、笔记、逐字引文和来源信息。服务端验证引文确实存在于对应原文；无有效引用时将回答标记为证据不足。知识库证据不足时可显示独立的模型补充，并明确标记其不受个人资料引用支持。

Embedding 临时失败时降级为 Postgres 关键词检索，不声称使用混合 RAG。

## API 与界面

扩展 `POST /api/ai/ask`，接收问题、最近会话和范围筛选，同时兼容现有 `noteIds`。响应返回知识库回答、模型补充、可信引用、证据状态、检索模式和实际范围。

新增幂等索引补齐、索引状态和失败重试接口。AI 能力接口增加 Embedding 配置状态和当前检索模式。

沿用右侧 Mine Copilot，增加全库或筛选范围、索引进度、失败重试、新对话和分区回答。引用继续打开对应笔记并定位原文。

## 验收

- 单元测试覆盖分块、中英关键词、融合排序、来源多样性、追问降级、内容哈希和引用校验。
- API 测试覆盖全库与筛选、多轮、索引状态、重试、旧请求兼容、基础模式和关键词降级。
- pgvector 集成测试覆盖迁移、向量与全文查询、任务锁、重启续跑、更新替换和删除级联。
- 所有查询强制用户隔离，日志不得包含问题、正文、引用、密钥或连接串。
- 固定评测集至少包含 30 篇中英素材和 20 个问题；正确证据块进入前 5 的比例不低于 90%，有效引用 100% 来自原文，跨用户泄漏为 0。
- `pnpm lint`、`pnpm test`、数据库集成测试和 `pnpm build` 必须通过；暂存环境确认素材在 60 秒内可检索。

## 上线

先在暂存环境启用 `vector` 扩展并执行迁移，再发布应用和 Embedding 配置。旧素材按用户后台补齐，索引未完成时允许查询已就绪内容并显示实际覆盖。

正式上线前轮换 Neon 数据库密码，并更新部署平台 `DATABASE_URL`。真实密钥和连接串不得写入仓库。
